Word Hopper — Final Considerations & Summary

Edge cases, polish details, and complete design recap

1. Edge Cases & Missing Considerations

▼ Two words with same first letter
WordSpawner guarantees different first letters. If pool exhausted, retry until satisfied. Never show "leaf" + "love" together.
▼ Player types while mid-air
Typing is always allowed. If player completes a word mid-jump, the current jump is overridden — new target height applied immediately. Physics recalculates velocity to reach new height.
▼ Player types wrong letter mid-word
Word flashes red (200ms), progress resets to 0. Must retype from first letter. The other word remains available — player can switch by typing its first letter instead.
▼ No input when obstacle arrives (skip)
If upper-only obstacle → player runs through gap, no jump, 0 bonus.
If lower-only obstacle → player MUST jump or die. Game auto-jumps at minimum height as last resort? NO. If you didn't type, you didn't jump. You die. This is the core tension.
▼ Upper-only obstacle + skip = free pass?
Yes. This is intentional strategy: safe path (skip, 0 bonus) vs. risk path (type, +bonus). The score system makes skipping non-viable for high scores.
▼ Multiple obstacle groups on screen
Yes at high speed. Only the NEAREST upcoming obstacle group accepts typing input. Farther groups are visible but dimmed. Player focuses on one at a time.
▼ Window resize / mobile
Canvas is fixed 800×450, CSS-scaled to fit viewport. Phaser handles scaling. Mobile: not supported in MVP — typing on touchscreen is a different game. Add later if needed.
▼ Audio feedback
MVP includes 4 sounds: type-correct (soft tick), type-wrong (low buzz), jump (whoosh), death (thud). All short (<200ms). Optional — game is playable muted.

2. Complete Design Summary

GAMEPLAY • Endless runner, character runs right, world scrolls left • One-hit death, instant restart • 3 difficulties: Easy (3-5 char), Medium (6-10 char), Hard (10+ char) • Two words per obstacle, first letters always differ • Words float in the gap, bound to obstacle, scroll together • Position mapping: upper word = high jump, lower word = low jump • Type correct → letters turn green, complete word → jump • Type wrong → flash red, reset progress, can switch to other word • Skip typing → survive if gap allows, but 0 bonus score • Speed: 0-500m fixed → 500-1500m +1%/3 obstacles → 1500m+ +1%/obstacle, cap 2.5x SCORING • Base: +1/tick (survival) • Word bonus: +10 × word_length × current_speed • Skipping = safe but no bonus → high scores require typing OBSTACLES • 6 plant types: Cactus, Bramble, Mushroom, Venus Flytrap, Tree Stump, Hanging Vines • 3 layout types: upper+lower (70%), upper-only (15%), lower-only (15%) • Gap height random: [2.5×, 4.5×] player height • Single obstacles: upper-only = skippable, lower-only = must jump or die SPACING • Min spacing = scroll_speed × (char_count × 0.25s + 0.8s) × 1.3 safety factor • Obstacles + words appear simultaneously on the right UI • HUD top-right: Score (label left, value right) + Speed (label left, value right), monospace grid • Menu: Title → click difficulty → SPACE or click START • Death: Score screen with stats (words typed, WPM, best word) → SPACE → menu • All English, words all lowercase TECH • Phaser 3 (Canvas) + TypeScript + Vite • Scenes: Boot → Menu → Game → Death • Systems: TypingSystem, WordSpawner, ObstacleSpawner, ScoreSystem, SpeedManager • Word lists: static JSON (easy: 1631, medium: 2756, hard: 1543) • Deploy: static site (any CDN) • Test: Vitest (unit) + Playwright (e2e)
